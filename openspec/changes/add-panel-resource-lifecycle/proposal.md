## Why

Paneon 的每个运行面板目前都长期保留独立 Node/Vite 执行环境，关闭标签页不会释放，服务重启又会逐个重建未关闭实例。持续创建面板将累积内存、监听器和恢复成本；不能依赖用户或 Agent 记得逐一关闭。

## What Changes

- 分离实例是否开放、执行环境是否驻留：默认允许自动休眠，访问或调用时按需恢复，显式关闭仍是另一项操作。
- 使用浏览器可见性租约、进行中调用计数和执行资源配额决定回收；隐藏页的自动查询不再维持默认面板常驻。
- 提供明确声明的常驻模式，供依赖服务端内存或需要后台持续工作的自定义面板使用；不自动判断任意代码是否可以重启。
- Git/PR 的展示数据与批注来源由浏览器持有；提交携带当次来源、原文和位置，后台校验完整请求并保存事件，不依赖旧进程的快照、session 或 listing Map，不新增快照落盘要求。
- 已编译静态资源按内容共享，独立提供页面；重启不批量启动休眠实例。实例查询直接使用主键，清理无引用构建缓存。
- **BREAKING**：实例状态改为 `open / closed / unavailable`，新增独立执行状态；默认面板的服务端模块状态不承诺跨休眠保留。修改 SDK/HTTP/CLI/指南的对应契约，不添加旧字段兼容层。

## Capabilities

### New Capabilities

- `panel-resource-lifecycle`：运行资源按需分配、可见性租约、安全回收、常驻声明、资源上限、冷启动和有界缓存。
- `browser-owned-review-annotations`：批注始终绑定当时展示的内容；组件及页面拥有展示数据和来源，事件携带足够的原文证据，后台重建不改变批注语义。

### Modified Capabilities

无。`openspec/specs/` 当前没有已归档能力；本 change 明确替代已有 runtime change 中“未关闭实例均常驻并在启动时恢复”的行为，不改动其他在途 change。

## Impact

单一仓库 `paneon`，分支 `0.0.x`，本次修订基线 `a32404d`（初稿基线 `cf5a4af`），另有未提交的 shutdown 改动和 runtime logging 设计，实施时必须保留。涉及运行时、SDK、编译产物路径、HTTP/CLI、面板宿主、首页、语言词典、Git/PR 场景及 skill 指南。复用现有 Vite、SQLite 和 WebSocket，不增加后台任务调度系统或业务数据库。

本次只产出设计，尚未授权实现。仅默认超时/配额与常驻策略 B1–B3 仍待用户在 design.md 开头拍板；原 C1 快照落盘决策已撤销，其编号不复用。组件数据归属和批注当次内容语义已确认。
