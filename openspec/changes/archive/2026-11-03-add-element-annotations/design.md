## Context

The approved preview uses the page's shared annotation store/editor. Its temporary DOM bridge must become framework-owned element registration. Existing page adapters and strict event schemas currently understand only author-defined references, so automatic references must pass through the common schema and bypass business-specific source checks.

## Goals / Non-Goals

**Goals:** Implement the reviewed desktop interaction without author wrappers; reuse all existing draft/editor/directory/submission behavior; keep generated references compact and explicit.

**Non-Goals:** New runtime APIs, source-code mapping, a page/revision payload protocol, cross-refresh recovery, automatic stale-content matching, image recognition, mobile work, release/commit work, or speculative business validation.

## Decisions

1. Keep `AnnotationTarget<TRef>` as the generic building block. Export an element-ref type/schema/recognizer; common schema composition and page submission/controller values accept author refs plus element refs. Author adapters continue receiving their own targets; framework element targets use their registered rendered elements. Supplied panel validators/mappers route element annotations through the shared payload without forcing file/row/diff identities onto them.
2. The enabled page owns one private picker alongside its existing controls. DOM paths always use the page body as their root, including picks made within an overlay, so references need no extra root/page discriminator. Ancestor choices stay within the current overlay's containing dialog when one is open; framework controls are excluded. This includes file-preview overlays whose drawing layer is separate from the content. Register the actual Element, including SVG, and retain it for saved drafts. When the user explicitly picks a different node with the same target key, replace the old node's registration; do not attempt automatic remount recovery. Object geometry uses its own bounds; Mermaid supplies its specialized SVG bounds explicitly instead of a general descendant-SVG heuristic.
3. The existing floating directory becomes a joined capsule: icon selection on the left, existing directory trigger on the right. Right-side dragging moves the whole capsule. Normal hover/click behavior remains. Selecting closes the directory; explicitly opening the directory exits selection. Existing disabled/submission/editor states remain authoritative.
4. Modes are browsing, picking, and reviewing a selected range. Picking intercepts content pointer/click actions, outlines the hit element and locks its visible ancestor chain. Review shows a popup beside the selected bounds and follows scrolling/resizing. Left expands to a parent, Right narrows toward the initially selected child; Enter opens the existing editor. Escape or Cancel clears the range and returns to picking; Escape without a range exits the mode. Editing keeps its existing Escape behavior. Opening the editor ends the picker.
5. References are exactly `{element:{path,tag,excerpt}}`, without page or revision. Excerpts use aria-label, otherwise textContent, collapse whitespace, retain the first `ELEMENT_ANNOTATION_EXCERPT_LENGTH = 30` grapheme clusters via Intl.Segmenter, and append `…` only when longer. This is an excerpt, not an AI summary. No additional alt/image interpretation is added.
6. Use the existing schema and registration checks. Add only element-shape schema composition and UI routing needed for the requested behavior, with no new stale/path/content rejection policy. Documentation describes DOM-path limitations rather than adding version checks.
7. Render element-target outlines within the shared annotation surface, reusing clipped target geometry and the actual element's border radius. Keep saved boundaries faint, without a fill; emphasize only the hovered/focused annotation, with the open editor taking precedence. Markers and directory rows share private UI preview state. Nested annotations retain separate boundaries, deletion removes the matching boundary, and the overlays do not capture pointer events. Author-defined text/media styling remains unchanged.
8. Both existing-annotation editing entry points use the matching marker identity as their anchor, including the specific target of multi-target annotations. Directory editing still waits for location and scroll stability before opening. Shared geometry then resolves the current marker position and uses the same alignment and collision handling as a marker click.
9. When a generated element target is hidden or removed at directory-edit time, open the existing editor directly at the viewport's bottom-right with 16px clearance, preserving its id, targets and comment. Check rendered visibility independently of viewport intersection so an offscreen element still uses normal scrolling and marker anchoring. This is an explicit editing placement, not exception recovery. Do not restore tabs, remount content, guess a replacement node, or change author-defined source/media location and validation. Target changes during an open editor remain outside this follow-up.
10. Use a limited, zero-configuration top-bar heuristic: visible fixed/sticky elements at least half the viewport width and no more than one-third its height. Exclude sticky candidates with `top:auto` at collection time: horizontal Diff row gutters cannot become top bars and should not be measured on every scroll frame. Merge bars connected to the viewport's top by gaps of at most 16px, then reserve 12px below them. Annotation controls and a bar's own annotation targets are excluded. Collect candidates on content/registry changes and measure their rectangles on scroll/resize; observe their sizes. Do not scan the whole DOM on every scroll or attempt general side-panel/irregular-occlusion detection. Existing nested-container and Diff-header clipping remain in use.
11. During generated-element location, use the available height to choose a focus area. If the element fits, center its full height. Otherwise center its opening half-screen portion, placing the target top one-quarter of the usable height below the available area's top. Temporarily supply scroll margins to native scrolling, wait for settled geometry and restore the author's inline margins. If scrolling has pinned or unpinned a sticky bar, apply one measured correction before opening the editor. Author-defined source/media location remains unchanged. The shared surface clips markers below the measured bars, and the existing editor uses the same top boundary through its current collision-padding support.

## Risks / Trade-offs

- DOM structure can change after selection → retain the actual node for this session; do not promise relocation after reload or reinterpret positions against changed content.
- An existing strict business schema rejects automatic refs → common annotationValueSchema accepts the new shape, and supplied source validators/mappers route element refs separately while preserving old source checks.
- Tree wrappers can have identical bounds → retain the preview's visible, distinct-bounds ancestor choices so range changes remain perceivable.
- Full-page and nested scroll geometry differ → reuse the existing clipping and positioning primitives, with targeted SVG/card/scroll tests.
