## Context

Git review 已有多仓库浏览、浏览器内原始快照和完整更正事件。输入列表固定，提交校验只认识当前配置的仓库。批注编辑器正在单独改造，本变更不修改它。

## Goals / Non-Goals

**Goals:** 实现已审阅用例中的绝对路径添加、目录浏览、工作树去重、非当前且没有未提交批注时移除，以及稳定的自足反馈。

**Non-Goals:** 相对路径、clone、删除磁盘仓库、全局收藏、列表或草稿跨重载恢复、系统原生对话框集成。

## Decisions

- 路径 schema 在浏览器检查绝对路径形式，Node 再按宿主平台校验；Git 根目录用 rev-parse 和 realpath 规范化。不同 worktree 分别管理。
- 用现有 Dialog、Input、Button、Empty、Spinner 组合“浏览…”目录选择，server action 列出所选绝对目录下的子目录。不使用上传控件，因为它不能提供服务端所需的绝对路径。
- 初始仓库先解析真实目录；失败信息返回界面，不隐藏错误。活跃列表保存在 React 状态，读取动作始终传入最新列表，并剥离只用于初次导航的 initialView。
- 用共享 useAnnotations 获取已保存草稿。将每个仓库的当前批注与最后成功提交的原始草稿比较，覆盖新增、修改和删除。失败不更新基线。
- 移除前检查当前仓库和未提交改动。已成功提交且被移除的意见从可编辑草稿中移出，保留其已提交来源片段；后续完整更正合入这些固定片段，避免意外撤回。移除时清理相应浏览状态、文件缓存和原始快照。
- Git 来源统一携带真实 repositoryPath，初始仓库和人工添加使用相同事件结构。已移除来源验证使用保留的身份表，保持后端无状态且不重读磁盘。
- 添加及目录浏览采用请求序号；取消、移除、切换后的迟到结果不改变当前页面。checkout 和提交期间禁止增删。

## Risks / Trade-offs

- [绝对路径破坏旧输入] → 更新技能引用、fixture 和校验测试，明确错误，不隐式展开相对路径或 ~。
- [更正会完整替代旧事件] → 保留被移除仓库已成功提交的固定片段，测试跨仓库后续更正。
- [目录选择运行在本地服务端] → 界面显示真实绝对目录，选择仅回填路径，仍须显式添加并验证 Git 仓库。
- [用户未提交的编辑器代码] → 不编辑相应源文件，构建和验收使用当前工作区完整代码。
