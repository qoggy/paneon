# 先定位根因，再做最小修复

修复 Bug 前，必须通过日志、复现、运行数据等证据定位根因，确认触发条件和失败路径。日志不足时先补充必要的诊断日志或复现手段；根因未确认前，只能进行调查、诊断和复现验证，禁止修改功能逻辑来尝试修复。

根因确认后，只针对根因做必要的最小修复，并验证原触发路径不再复现，补充与改动相称的回归验证。禁止根据猜测在多处添加补丁、兜底、重试或兼容分支；即使问题表面消失，也不能替代根因证据。

**Why:** 猜测性补丁会隐藏真实故障、扩大改动范围，并使代码库越来越难维护。
**How to apply:** 修改功能逻辑前能明确说明现象、根因和支持证据；证据不足就继续调查或补诊断，不以试错式功能改动代替定位。修复不夹带无关重构或防御逻辑。
