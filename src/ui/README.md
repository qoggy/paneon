# Component provenance

Empty is vendored from the official Base UI `base-nova` registry recorded in `upstream.json`, with only a local utils import and project formatting. Its public exports include the container, header, title, description, media and content components.

Context Menu is vendored from the official Base UI `base-nova` registry recorded in `upstream.json`, with local utils imports and Lucide icons. Its public exports support right-click actions through `ContextMenu`, `ContextMenuTrigger`, `ContextMenuContent` and `ContextMenuItem`.

Base components were originally vendored from the official shadcn registry's `new-york-v4` style. All interactive primitives now use `@base-ui/react` 1.9.0, with the Base UI `base-nova` registry consulted on 2026-10-25 for composition and positioning. `upstream.json` retains the original source hashes and records the migration reference URLs and hashes separately. Original Neutral tokens, sizing and layout are retained; local adaptations include relative imports, formatting and `useUI` localization. Builds and installed panels use the local source and do not fetch upstream. Preserve `UPSTREAM-LICENSE.md` when redistributing these sources.

`components.json` records the Base UI generator configuration: TypeScript, React client components, Lucide icons, CSS variables, and the default Neutral color. `styles.css` contains the official Neutral light/dark variables from the recorded color registry, Tailwind theme mappings, and upstream base rules. `upstream-tailwind.css` comes from the fixed `shadcn@4.22.1` package (the recorded hash describes the upstream bytes before formatting). No Paneon palette, font, control sizing, or radius overrides are introduced.

Page, Section and Stack add only composition layout. StatusBadge re-exports Badge. Markdown uses react-markdown, remark-gfm, and github-markdown-css styles scoped by `markdown-body`. Its ordinary code blocks share CodeBlock's Shiki tokenizer, static local grammars and GitHub Light/Dark token colors, following the current theme while retaining Markdown's existing block styles. Untagged and unsupported languages remain plain text; inline code and custom `pre`/`code` renderers retain their existing behavior. Author-provided rehype syntax colors remain intact; these code blocks receive the same default toolbar and wrapping controls unless `pre` or `code` is overridden. Ordinary code blocks show a language label (Plain Text when untagged), a word-wrap toggle and Copy code with hover/focus tooltips. Wrapping is on by default; turning it off scrolls only the code, keeping the toolbar visible. Copy sends the code text, including whitespace and line endings, through the existing host clipboard bridge and reports success or failure with a toast. Highlighted code retains its original text and Markdown annotation source coordinates. All rendering dependencies are distributed locally. Package-lock pins the resolved dependency versions.

`Markdown` recognizes a single leading YAML frontmatter block and renders its fields, values and nested lists before the Markdown body as one document. It adds no metadata heading, type labels, counts, source view or collapse controls. Strings are plain text, numbers retain their original precision, and anchors, aliases and explicit tags retain their source spelling without expanding references or executing custom tag handlers. Parsing uses YAML 1.2 Core; merge keys are ordinary keys. A block must begin at the start of the string (an optional BOM is allowed), open with `---` and close with a standalone `---` or `...`; LF, CRLF, CR and trailing horizontal whitespace on delimiters are supported. Without a complete envelope, ordinary Markdown rendering applies. Invalid YAML remains visible as literal source and parser errors are reported to the console. Full YAML streams with directives or multiple documents belong in fenced code blocks. Set `frontmatter="off"` to preserve ordinary Markdown semantics for intentionally ambiguous input.

Inside Paneon, default Markdown links to local files open a read-only source Sheet with syntax highlighting, line numbers and Copy path. Relative paths use the panel's working directory; pass `sourcePath` when rendering a Markdown file so references use that file's directory instead: `<Markdown sourcePath="docs/plan.md">{source}</Markdown>`. Absolute paths and local `file://` URLs are supported. `#L12` and `#L12-L18` scroll to and highlight the source lines; other fragments on a file link open its source without line selection. Standalone `#fragment` links use the heading navigation described below. File reads use the authenticated bridge and current panel revision, not a static-file URL. Opening captures the current file; the displayed source stays unchanged until the reference is opened again. Preview accepts regular UTF-8 text files up to 1 MiB and reports missing, unreadable, binary and oversized files without showing partial content. Closing returns focus to the original link without moving the document.

Headings receive instance-scoped IDs using GitHub heading slug rules. The default link renderer resolves standalone fragments such as `[Install](#install)` within the current Markdown and scrolls the target into view without navigating or reloading the panel. Chinese and percent-encoded fragments work; repeated headings use `-1`, `-2` and subsequent suffixes. Author-provided rehype IDs are preserved, and custom heading renderers must forward their `id` prop. Unresolved fragments retain native in-document behavior. Markdown does not generate a table of contents automatically.

HTTP/HTTPS links open through the host in a new browser tab. Unsupported protocols, including `vscode://`, and filtered empty destinations render as plain, non-focusable text. Inline-code paths remain text. Custom `components.a` renderers own their link behavior. Outside Paneon, `UIProvider.onReadFile` can supply a `{href, sourcePath?} => Promise<{path, text}>` reader; without a reader local references render as text.

Frontmatter and body annotations address the complete original string, including its BOM and line endings. Unchanged YAML text and simple quoted strings support character ranges. Scalars transformed by escapes or folding support selection of the complete displayed value, mapped to its original YAML scalar; unmappable internal boundaries do not produce partial annotations.

Mermaid diagrams expose unobtrusive expand and more-options icons on hover or keyboard focus. The viewer has no visible title; it supports zoom, actual size, fit, drag-to-pan, PNG download and closing via its icon, backdrop or Escape. Its menu copies the original Mermaid source, copies a PNG or downloads a PNG. Images retain the rendered theme and fonts, cover the complete diagram independently of viewer zoom/pan, and use an opaque theme background. Markdown Mermaid fences inherit these interactions. The compiler supplies `UIProvider.onBrowserAction` through the authenticated panel bridge so clipboard and download operations run in the host without relaxing the iframe sandbox. Outside Paneon, UIProvider uses the same browser operations directly.

Build the public library with `vite build --config vite.ui.config.ts`. Its outputs are `dist/ui/index.js` and `dist/ui/theme.css`; the runtime includes the theme in each isolated panel, separately from the host stylesheet.

The library build reuses the panel action extractor for component modules. Its current source restrictions also apply here: retain initialization in referenced declarations, avoid top-level expression statements such as `Component.displayName = ...`, and use bare side-effect imports only for CSS. The source rewrite currently does not emit source maps. Components must not assume that a generated action proxy implies a running panel; standalone rendering keeps native image URLs and requires an explicit text reader for local file links.

Loaded Markdown images open the shared image viewer on click, Enter or Space. The viewer supports zoom, actual size, fit, drag-to-pan, and closing via its icon, backdrop or Escape, returning focus to the image. Image and default Markdown-image viewers also offer Download original through the same action as their more menu, preserving the selected image's original format and bytes; Mermaid keeps Download PNG. While an image action is in progress, the viewer download shows Spinner and is disabled. Linked images retain their navigation behavior; broken or still-loading images do not open a viewer. Images inside Mermaid diagrams belong to the diagram viewer. Custom `components.img` renderers retain their props and also support click-to-expand when they render an image and allow its click event to bubble. Panels allow HTTP and HTTPS image sources directly through the browser, including in the expanded viewer. Loading an external image makes a direct browser request to its source; the script-src and connect-src directives remain unchanged. Images requiring authentication or blocked by their source server's embedding policy may remain unavailable.

`Image` is the reusable single-image component: `<Image src="./picture.png" alt="Screenshot" className="max-w-md" />`. Its public props are required `src` and `alt`, optional `sourcePath` and `className`. It owns loading, inline failures, hover/focus controls and the existing click/keyboard image viewer. Both remote and local images show the shared `Spinner` until the browser loads the image; local loading also covers the file read. Cached images are recognized on attachment. Images inside links retain their link behavior. The component uses native image URLs outside a compiled panel.

Markdown's default image renderer uses the same Image implementation. Inside a compiled Paneon panel, ordinary local images such as `![Screenshot](./picture.png)` and absolute filesystem paths load automatically through Image's private query action. Relative images use `sourcePath`'s directory when supplied, otherwise the panel's working directory, matching local text-link resolution. PNG, JPEG, WebP, GIF, SVG and AVIF files retain the existing 20 MiB limit; unreadable, unsupported or undecodable images show an inline failure. The viewer reuses the loaded image data and Copy path preserves the original reference. Local images are read on mount or reference changes; refresh the page to reread disk changes. No panel-authored reader, image import, custom renderer or additional runtime endpoint is required. HTTP/HTTPS sources keep their browser-loading behavior; service assets should use explicit HTTP URLs rather than filesystem-style absolute paths.

Image and Mermaid use the same vertical expand/more toolbar in a separate right-hand column aligned with the top of the content, revealed on hover or keyboard focus and retained while its menu is open. The toolbar is outside Mermaid's scrolling content; it does not make a fitted diagram acquire a vertical scrollbar. Images no longer show a path/URL tooltip. The image menu offers Copy path (the original src, including a relative path or remote URL), Copy image (PNG pixels for the clipboard), and Download original (unchanged file bytes and format). The existing authenticated browser bridge performs these operations in the host, preserving the iframe sandbox; standalone usage performs them directly. In-progress actions show Spinner and success/failure uses toast. Inside compiled panels, remote copy/download reads the original bytes on demand through Image's existing serverAction and passes a Data URL to the host; display and expansion remain native browser requests. This preserves host CSP and iframe connect-src without new runtime routes. Browser decoding of Data URLs preserves download bytes without a fetch. Standalone remote operations follow the embedding page's browser policy. Clipboard permissions and source availability still apply; private browser cookies are not forwarded by the action. Failed operations use toast without substituting a PNG for an original-file download. Linked images retain navigation and do not receive nested action buttons. The default Markdown URL filter does not accept `data:` image addresses.

Enable annotations with `usePageAnnotations({ onSubmit, adapter?, disabled?, allowEmptySubmit?, onRequestEdit? })` from `@qoggy/paneon/ui`. Paneon's page environment automatically owns one internal annotation session, contextual editor and floating bottom-right directory; Root, Menu and SubmitButton are not public exports. Pages without the configuration hook show no annotation controls. Outside the panel runtime, `UIProvider` supplies the same environment. `AnnotationText` accepts a business `target`, required `children: string` and optional `className`: `<AnnotationText target="source">{text}</AnnotationText>`. `useAnnotations` provides the shared draft/controller. Editor Save only retains a browser-memory draft; the required `onSubmit` callback owns validation and delivery. `allowEmptySubmit` permits an empty correction, and a disabled page can supply `onRequestEdit` to offer **Correct feedback** in the directory. The [authoring guide](../../skills/paneon/references/authoring.md#annotations) contains a complete example. SDK types are `Annotation`, `AnnotationValue`, `AnnotationTarget` and `AnnotationTextRange`, with `annotationValueSchema` validating the complete value. Annotated Markdown automatically enables annotations in linked file previews, inheriting its unchanged `ref`. The optional JSON `sourceRef` on a target distinguishes the displayed file's `{path, snapshotId}` from the Markdown source; SDK schemas accept this metadata without widening `ref`. No extra configuration is required.

For repeatable real-browser checks, after the project dependencies and Chrome are available, run `node tests/browser/ui.mjs`. It renders the test-only `tests/fixtures/panels/components-panel.tsx` gallery plus behavior variants inside an `allow-scripts` sandbox, blocks external HTTP requests, and checks all component families. `PANEON_TEST_BROWSER_CHANNEL` can select another Playwright browser channel. `node --test tests/ui-bridge.test.ts` checks the host bridge identity boundary.

Component composition uses Base UI's `render` prop instead of `asChild`. Dialog and Sheet content expose `initialFocus` / `finalFocus`; Popover content accepts a native Positioner `anchor` (including a virtual element). Close policy belongs to the Root's `onOpenChange` event details. Accordion uses `multiple` and array values; Checkbox uses a boolean `checked` plus `indeterminate`; Select can return `null` for no selection. Menu actions use `onClick`. Styling targets Base UI's `data-open`, `data-closed`, `data-checked`, `data-active` and positioning variables such as `--available-height` and `--transform-origin`.

Base UI 1.9 tooltips are visual hints and do not add a `tooltip` role. Icon triggers keep their own `aria-label`; browser checks locate the visible `data-slot=tooltip-content` popup.

`DiffView` is a public, repository-independent text comparison. Pass `oldText` / `newText` or a model from `createDiffModel` (`@qoggy/paneon/sdk`). It supports side-by-side and unified modes, navigation, contextual/full source, resizable columns, optional revision/path metadata and `onCollapse`. A file heading is never rendered. Metadata appears only when at least one path or revision is nonempty; missing values stay blank. `fileOnly` and `showFileHeading` are not public props. Supplied Git/PR pages handle non-text sources themselves. `annotationTargets={{ old, new }}` opts into the page session enabled by `usePageAnnotations`; each supplied generic reference is delivered unchanged, and an omitted side is not registered. Text offsets address the complete side source. `DiffViewHandle` exposes async `reveal(DiffLocation)` and instance-scoped `getRanges(DiffLocation)`; the page resolves business references and restores snapshots before revealing display coordinates. `sourceId` and `locateTarget` are not props. Git reads, source identity and submission policies remain outside the renderer.

Diff highlighting follows two levels: pale green/gray/blue line backgrounds represent additions/deletions/modifications; stronger inline marks distinguish inserted, removed and replaced words within a modified block. The private `diff-presentation.ts` compares complete changed blocks with jsdiff and `Intl.Segmenter`, then aligns lines using common words on that token diff's chosen edit path. Wrapped or joined lines that retain matched words remain modified, including when they have no 1:1 row partner. This is textual matching, not AST or moved-code detection. The private `CodeText` renderer intersects these marks with the existing Shiki tokens, retaining source text and UTF-16 annotation offsets. Inline foregrounds retain their syntax hues while mixing toward black in light mode and white in dark mode for legibility. Both side-by-side and unified views use the same presentation. To bound detailed comparison, blocks exceeding 20,000 combined word tokens or 1,024 token edits retain complete line-level rendering without inline marks. The patch model, hunks and navigation boundaries are unchanged.

`Markdown` accepts optional `annotationTarget`, using the same JSON reference model as `AnnotationText.target`. `<Markdown>{source}</Markdown>` requires no annotation Root. `<Markdown annotationTarget="plan-a">{source}</Markdown>` registers exact original Markdown coordinates inside an existing Root. Independent documents, including identical strings, need distinct stable targets; their targets are delivered unchanged as `ref`. While a target has saved or in-progress annotations, the renderer retains the annotated source instead of silently replacing it after a prop update. Removing those drafts permits the newer source to render. This protection is scoped to the current Root/browser session; it is not cross-reload persistence. Existing component overrides, GFM and Mermaid remain available; diagram interiors and unmappable custom transformations are not selectable text. Do not mount an additional surface or build a second annotation state machine.

Promoted components read the existing `useUI()` and core dictionaries. User content is never translated. The plain source mapper and range checks remain private implementation details; no new public text-range validation API is introduced. Supplied-page correction receipts remain in the skill.

## Tree

`Tree<T>` displays synchronous, fully loaded hierarchies using the caller's original objects. It does not read files, sort paths or require Git fields. Import `Tree`, `TreeProps`, `TreeHandle`, `TreeItemState`, `TreeItemPresentation` and `TreeRevealError` from `@qoggy/paneon/ui`.

```tsx
type Item = { key: string; name: string; nodes?: Item[] };

<Tree
  items={items}
  getItemId={(item: Item) => item.key} // Unique and stable within this instance.
  getItemLabel={(item) => item.name} // Plain text for accessible naming and default search.
  getItemChildren={(item) => item.nodes} // undefined = leaf; [] = empty container.
  defaultExpandedIds={['prompts']}
  onSelectionChange={(id) => setSelected(id)} // Click selects without opening.
  onAction={(item) => openItem(item)} // Leaf Enter/double-click returns the original object.
  searchTerm={search}
  aria-label="Proposed files"
/>;
```

`renderItemContent(item, state)` customizes display content only; keep buttons, links and inputs outside it. State contains `selected`, effective `expanded`, `isBranch` and one-based `level`. `getItemPresentation` sets row `className`, `style`, `title`, `aria-description` and `data-*` values without overriding tree events. `className` styles the root; scrolling and toolbars belong to the containing page.

Selection and expansion are independently controlled with `selectedId` / `onSelectionChange` and `expandedIds` / `onExpandedChange`. Explicit user selection reports intent even when selecting the same ID again; unchanged base expansion does not notify. Undefined chooses internal state; null selection and an empty expansion array are controlled values. Internal defaults are `defaultSelectedId` (null) and `defaultExpandedIds` ([]), read once. Do not switch modes while mounted. Leaves are selectable by default; `isItemSelectable=false` limits selection only, preserving focus, expansion and leaf action. Deleted uncontrolled identities are removed and reported; filtering does not delete selection. Controlled identities remain the parent's responsibility.

Search uses case-insensitive label substring matching unless `isItemMatchingSearch(item, term)` is supplied. Matching nodes keep their ancestor paths; matching a container does not include unrelated descendants. Search temporarily expands matching paths without writing the base expanded IDs. Clearing search restores base expansion. Explicit individual container clicks still request base expansion changes; `expandAll()` expands the complete data, and `collapseAll()` is a no-op during search.

The root is a named group of native buttons. Click selects a leaf; Enter or double-click activates it. Container rows toggle expansion and do not invoke the leaf action. Space retains native click behavior; Tab moves focus without selecting. There is no APG treeview role, roving focus, Arrow/Home/End navigation, multiselect or lazy loader. `loading` marks the tree busy, suppressing the initial empty state while retaining supplied items; it does not cache old items. `emptyState` renders when the visible result is empty and loading is false.

```tsx
const tree = useRef<TreeHandle>(null);
const controller = new AbortController(); // Abort on view change or business cancellation.
await tree.current!.revealItem(id, { signal: controller.signal });
```

`revealItem` requests ancestor expansion, waits for controlled state to be returned and resolves after the mounted row can be scrolled with non-smooth nearest positioning. It does not select, focus, open or clear search. It waits without an implicit timeout if the parent does not accept; the required signal owns cancellation. Missing or filtered targets reject with `TreeRevealError.code` (`TREE_ITEM_NOT_FOUND` / `TREE_ITEM_FILTERED`). Cancellation, unmount, a new reveal or an intervening expansion command rejects the old call with `AbortError` and releases its listeners and queued scroll. Repeated calls to the same ID reveal again.

The [built-in Diff Review panel](../../skills/paneon/assets/panels/diff-review/panel.tsx) demonstrates non-Git adaptation and composes a page-owned file-read query, DiffView and explicit annotation submission; Git Review keeps its path construction, sections, status rendering and toolbar in the skill's adapter.

### Resizable

`ResizablePanelGroup`, `ResizablePanel` and `ResizableHandle` follow [shadcn Resizable](https://ui.shadcn.com/docs/components/base/resizable), backed by `react-resizable-panels` v4. Use `orientation="horizontal"` or `"vertical"`; sizes accept explicit strings such as `"20%"`, `"9rem"` and `"320px"`. Numeric sizes mean pixels. A handle is a narrow separator by default; `withHandle` adds a visible grip. The library owns pointer resizing, size constraints and separator accessibility. `groupRef` accepts the exported `ResizablePanelGroupHandle` for imperative layout operations.

```tsx
<ResizablePanelGroup orientation="horizontal">
  <ResizablePanel defaultSize="20%" minSize="9rem">
    {fileTree}
  </ResizablePanel>
  <ResizableHandle aria-label="Resize file list and diff" />
  <ResizablePanel minSize="20rem">{diffView}</ResizablePanel>
</ResizablePanelGroup>
```

The built-in Git Review and Diff Review panels compose these primitives through `assets/shared/file-review-split.tsx`. That panel layer retains the 1px line, 12px mouse target, existing pixel keyboard steps, Escape cancellation and session-local layout memory; it does not put Git or diff data into the public primitives.

Git Review's history layout uses nested horizontal/vertical groups in `assets/panels/git-review/history-workspace.tsx`. It retains adaptive defaults, minimum widths/heights and session proportions; the opposite outer column is disabled only during a column gesture so reaching the commit-list minimum does not resize that other column.

DiffView's internal old/new divider uses the same Resizable primitives through `diff-columns.tsx`. One sizing track drives the path headers and all hunk tables, retaining aligned rows, independent horizontal scrolling and the original text DOM. The ratio survives unified/side-by-side switching; whole-file additions and deletions remain full-width without a divider. Internal separator ARIA values use the library's percentage units.

Side-by-side DiffView also shows a vertical scrollbar and change overview on each outer edge. Each overview uses its own source positions and the existing add/delete/modify colors, including thin marks on the empty side of insertions or deletions. Marks are decorative: clicking the track or dragging either thumb scrolls both sources through their shared correspondence track. Wheel scrolling, keyboard scrolling, bounded viewports and document flow use the same mapping. Unified and whole-file single-column views retain their ordinary scrollbars.
