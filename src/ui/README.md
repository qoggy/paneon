# Component provenance

Empty is vendored from the official Base UI `base-nova` registry recorded in `upstream.json`, with only a local utils import and project formatting. Its public exports include the container, header, title, description, media and content components.

Context Menu is vendored from the official Base UI `base-nova` registry recorded in `upstream.json`, with local utils imports and Lucide icons. Its public exports support right-click actions through `ContextMenu`, `ContextMenuTrigger`, `ContextMenuContent` and `ContextMenuItem`.

Base components were originally vendored from the official shadcn registry's `new-york-v4` style. All interactive primitives now use `@base-ui/react` 1.9.0, with the Base UI `base-nova` registry consulted on 2026-10-25 for composition and positioning. `upstream.json` retains the original source hashes and records the migration reference URLs and hashes separately. Original Neutral tokens, sizing and layout are retained; local adaptations include relative imports, formatting and `useUI` localization. Builds and installed panels use the local source and do not fetch upstream. Preserve `UPSTREAM-LICENSE.md` when redistributing these sources.

`components.json` records the Base UI generator configuration: TypeScript, React client components, Lucide icons, CSS variables, and the default Neutral color. `styles.css` contains the official Neutral light/dark variables from the recorded color registry, Tailwind theme mappings, and upstream base rules. `upstream-tailwind.css` comes from the fixed `shadcn@4.22.1` package (the recorded hash describes the upstream bytes before formatting). No Paneon palette, font, control sizing, or radius overrides are introduced.

Page, Section and Stack add only composition layout. StatusBadge re-exports Badge. Markdown uses react-markdown, remark-gfm, and the light github-markdown-css stylesheet, scoped by `markdown-body`. CodeBlock uses Shiki's JavaScript engine, GitHub Light theme, and static local grammar imports; unknown languages are plain text. All rendering dependencies are distributed locally. Package-lock pins the resolved dependency versions.

Mermaid diagrams expose unobtrusive expand and more-options icons on hover or keyboard focus. The viewer has no visible title; it supports zoom, actual size, fit, drag-to-pan, PNG download and closing via its icon, backdrop or Escape. Its menu copies the original Mermaid source, copies a PNG or downloads a PNG. Images retain the rendered theme and fonts, cover the complete diagram independently of viewer zoom/pan, and use an opaque theme background. Markdown Mermaid fences inherit these interactions. The compiler supplies `UIProvider.onBrowserAction` through the authenticated panel bridge so clipboard and download operations run in the host without relaxing the iframe sandbox. Outside Paneon, UIProvider uses the same browser operations directly.

Build the public library with `vite build --config vite.ui.config.ts`. Its outputs are `dist/ui/index.js` and `dist/ui/theme.css`; the runtime includes the theme in each isolated panel, separately from the host stylesheet.

Annotations use `AnnotationRoot`, `AnnotationText`, `AnnotationMenu`, `AnnotationSubmitButton` and `useAnnotations` from `paneon/ui`. `AnnotationText` accepts a business `target`, required `children: string` and optional `className`: `<AnnotationText target="source">{text}</AnnotationText>`. The Root owns state and exactly one internal contextual surface. Pages do not mount a Surface or a Controls/Toolbar wrapper. The menu includes submission by default; `showSubmit={false}` allows a separately positioned submit button. Editor Save only retains a browser-memory draft. The Root's required `onSubmit` callback owns validation and delivery; the runnable [annotation example](../../skills/paneon/assets/examples/annotations/panel.tsx) validates the selected source, emits its declared event and shows its receipt. The [authoring guide](../../skills/paneon/references/annotations.md) includes the agent's events/ack consumption commands. SDK types are `Annotation`, `AnnotationValue`, `AnnotationTarget` and `AnnotationTextRange`, with `annotationValueSchema` validating the complete value. The former Feedback exports have been replaced rather than kept as aliases.

For repeatable real-browser checks, after the project dependencies and Chrome are available, run `node tests/browser/ui.mjs`. It renders the test-only `tests/fixtures/panels/components-panel.tsx` gallery plus behavior variants inside an `allow-scripts` sandbox, blocks external HTTP requests, and checks all component families. `PANEON_TEST_BROWSER_CHANNEL` can select another Playwright browser channel. `node --test tests/ui-bridge.test.ts` checks the host bridge identity boundary.

Component composition uses Base UI's `render` prop instead of `asChild`. Dialog and Sheet content expose `initialFocus` / `finalFocus`; Popover content accepts a native Positioner `anchor` (including a virtual element). Close policy belongs to the Root's `onOpenChange` event details. Accordion uses `multiple` and array values; Checkbox uses a boolean `checked` plus `indeterminate`; Select can return `null` for no selection. Menu actions use `onClick`. Styling targets Base UI's `data-open`, `data-closed`, `data-checked`, `data-active` and positioning variables such as `--available-height` and `--transform-origin`.

Base UI 1.9 tooltips are visual hints and do not add a `tooltip` role. Icon triggers keep their own `aria-label`; browser checks locate the visible `data-slot=tooltip-content` popup.

`DiffView` is a public, repository-independent text comparison. Pass `oldText` / `newText` or a model from `createDiffModel` (`paneon/sdk`). It supports side-by-side and unified modes, navigation, contextual/full source, resizable columns, optional revision/path metadata and `onCollapse`. A file heading is never rendered. Metadata appears only when at least one path or revision is nonempty; missing values stay blank. `fileOnly` and `showFileHeading` are not public props. Supplied Git/PR pages handle non-text sources themselves. `annotationTargets={{ old, new }}` optionally connects an existing `AnnotationRoot`; each supplied generic reference is delivered unchanged, and an omitted side is not registered. Text offsets address the complete side source. `DiffViewHandle` exposes async `reveal(DiffLocation)` and instance-scoped `getRanges(DiffLocation)`; the page resolves business references and restores snapshots before revealing display coordinates. `sourceId` and `locateTarget` are not props. Git reads, source identity and submission policies remain outside the renderer.

`Markdown` accepts optional `annotationTarget`, using the same JSON reference model as `AnnotationText.target`. `<Markdown>{source}</Markdown>` requires no annotation Root. `<Markdown annotationTarget="plan-a">{source}</Markdown>` registers exact original Markdown coordinates inside an existing Root. Independent documents, including identical strings, need distinct stable targets; their targets are delivered unchanged as `ref`. While a target has saved or in-progress annotations, the renderer retains the annotated source instead of silently replacing it after a prop update. Removing those drafts permits the newer source to render. This protection is scoped to the current Root/browser session; it is not cross-reload persistence. Existing component overrides, GFM and Mermaid remain available; diagram interiors and unmappable custom transformations are not selectable text. Do not mount an additional surface or build a second annotation state machine.

Promoted components read the existing `useUI()` and core dictionaries. User content is never translated. The plain source mapper and range checks remain private implementation details; no new public text-range validation API is introduced. Supplied-page correction receipts remain in the skill.
